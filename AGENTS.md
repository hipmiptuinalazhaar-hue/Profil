# HIPMI PT UIN Al Azhaar — Project Constitution

This repository is the official digital headquarters of HIPMI PT UIN Al Azhaar Lubuklinggau.

## North star
Every page must either **build trust, create value, demonstrate impact, or enable action**.

## Product standard
Build an institutional entrepreneur platform, not a generic student-organization website. The experience should feel 60% premium institutional, 20% entrepreneurial, 10% editorial, and 10% experimental technology.

The design must be credible in front of students, founders, senior entrepreneurs, university leaders, government, investors, media, and strategic partners.

## Non-negotiables
- No fake statistics, fake partners, lorem ipsum, dead CTAs, or fabricated businesses.
- No generic purple/blue AI gradients, excessive glassmorphism, random blobs, gratuitous glow, fake 3D objects, or template-SaaS composition.
- No visual system that looks mass-generated by AI. Every layout needs a clear hierarchy, editorial logic, and organizational context.
- Gold is a restrained accent, not a background wallpaper.
- Prefer purposeful editorial composition and real documentary photography.
- Preserve faces, clothing, body proportions, event context, and documentary truth in official photography.
- Never publish intentionally low-resolution, heavily compressed, upscaled, or visibly blurred leadership/documentation imagery.
- Do not process/remove portrait backgrounds until explicitly approved for the asset mastering phase.
- All BPH and all six Heads of Fields must have complete leadership-photo coverage before leadership implementation is considered done.
- Compartments/staff are represented by name and role only unless the founder explicitly changes that rule.
- Default to Server Components. Add client JavaScript only when interaction requires it.
- Design from 360px upward and respect reduced-motion preferences.
- WCAG 2.2 AA is the minimum accessibility target.
- Keep secrets server-side and validate all future mutation inputs on the server.
- Do not expose unfinished routes in sitemap or navigation as working functionality.

## International benchmark strategy
Use benchmarks as functional DNA, never as visual cloning:
- 40% Endeavor: entrepreneur ecosystem, multiplier effect, founder/business storytelling.
- 20% YPO: prestige, leadership, membership quality.
- 20% JCI: organization/member architecture, programs, events, impact.
- 10% World Economic Forum: institutional authority, partnership, insight hierarchy.
- 10% TED: documentary storytelling, media/editorial presentation.

The result must still look unmistakably like HIPMI PT UIN Al Azhaar Lubuklinggau.

## Quality gates
A phase is not complete because code exists or a commit was merged.

### Visual gate
No phase advances while the output still feels like a template, generic card grid, or AI slop.

### Asset gate
No public section is complete while required photography, logos, names, titles, or verified content are missing.

### Production gate
Any phase that changes production UI is complete only after merge, Cloudflare build/deploy, live-page verification, responsive review, and regression checks.

## Engineering targets
- Lighthouse Performance >= 90
- Accessibility >= 95
- Best Practices >= 95
- SEO >= 95
- LCP < 2.5 s
- CLS < 0.1
- INP < 200 ms

## Stack baseline
Next.js 16.3.3, React 19.3, TypeScript strict mode, Tailwind CSS 4.3, App Router, PostgreSQL-ready data architecture, Cloudflare Workers through vinext/Wrangler.

## Deployment policy
- GitHub is source/version control and review.
- Cloudflare is build, deploy, hosting, and runtime.
- **Do not add GitHub Actions or `.github/workflows` unless the founder explicitly reverses this policy.**
- Cloudflare build command: `npm run build:cloudflare`.
- Cloudflare deploy command: `npx wrangler deploy`.
- Build quality checks belong inside the Cloudflare build script, not GitHub Actions.

## Content principles
Copy must be specific, factual, human, concise, and professionally confident. Indonesian is canonical; English is a reviewed translation, not a machine-generated afterthought.

## Source-of-truth hierarchy
1. Verified organization data in `src/config` and `src/content`.
2. Architecture and phase decisions in `/docs`.
3. Database/CMS when those systems are introduced.

When information is unknown, omit it or show a truthful editorial empty state. Never invent it.
